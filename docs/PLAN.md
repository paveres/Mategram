# Mategram: план работ и логика каждой функции

Версия базы: **Telegram-iOS 13.2**. Нумерация функций совпадает с `docs/FEATURES.md`.
Источники логики: **S** Swiftgram, **G** Ghostgram, **N** Nextgram (разбор IPA). Сложность: **Л** лёгкая, **С** средняя, **Т** тяжёлая.

Решения по вашим последним сообщениям:
- Из списка убраны **#40** (кнопка поиска у таб-бара) и **#91** (поиск по настройкам). Остаётся **136 функций**.
- `team_id` убираем, bundle id **app.mategram.ios** (см. раздел 1).
- Режим призрака берём из Ghostgram (там реализация сильнее всего), остальное по логике Swiftgram там, где она проще и надёжнее.

## 1. Сборка: `team_id` и bundle id

**Можно.** `Make.py` требует ключи `bundle_id` и `team_id` в конфигурации, но IPA собирается с **фейковой подписью** и потом подписывается заново вашим Apple ID через Sideloadly, поэтому настоящий team id не нужен.

Что сделано и проверено:
- `py -3 scripts/mategram.py codesigning` переиздаёт 9 фейковых профилей Telegram под `MATEGRAM00.app.mategram.ios` (приложение и 8 расширений, группа `group.app.mategram.ios`). Профили читаются тем же вызовом `openssl smime -verify -noverify`, которым их читает `Make.py`.
- `py -3 scripts/mategram.py config` пишет конфигурацию: `bundle_id = app.mategram.ios`, `team_id = MATEGRAM00` (просто строка-заглушка), `enable_icloud = false`, ваши `api_id` и `api_hash` из секретов GitHub.
- Ваш рабочий workflow из `airagram-ios` (`mindgram.yml`) уже собирает на раннере `xcode-27`, значит образ с Xcode 27 у GitHub есть. Берём его как основу.

Оговорки (честно):
- Профили проверялись только на моём компьютере. Как их примет Bazel на macOS, покажет первая сборка. Запасной путь: собрать с `ph.telegra.Telegraph`, а `app.mategram.ios` задать в Sideloadly (Advanced options).
- Sideloadly с бесплатным Apple ID не даёт App Group и push. Приложение и расширения должны работать без App Group (запасной путь в хранении настроек, см. этап 0), иначе будет чёрный экран, как у вас уже было в AyuGram.
- Уведомления с сервера Telegram приходят только с настоящим профилем и push-сертификатом. На бесплатном ID их не будет.

## 2. Принципы (как мы пишем)

1. **Наш код отдельно** в `overlay/Mategram/*`, в файлах Telegram только вставки в одну строку (хуки). Обновление Telegram переносит хуки скриптом.
2. **Настройки как у Swiftgram**: ключ, значение по умолчанию, чтение из кэша без блокировок, прогрев при запуске; **реестр как у Ghostgram**: ключ объявляется один раз с типом, областью (общая или на аккаунт) и признаком «читают расширения».
3. **Решение о приватности принимается в ядре** (`TelegramCore`), а не в интерфейсе, и одинаково для приложения и расширений (как Ghostgram).
4. **Тяжёлое грузим лениво**: Metal, Vision, Core Bluetooth, аудио-цепочки создаются при первом использовании.
5. `TelegramCore` собирается с `-warnings-as-errors`: вставки без предупреждений.

### 4.1. Иконка приложения (Настройки, Оформление)

Как это устроено в Telegram 13.2 (проверено по коду): экран «Оформление» (`SettingsUI/Sources/Themes/ThemeSettingsController.swift`) уже умеет менять иконку. Список берёт из `getAvailableAlternateIcons` в `TelegramUI/Sources/AppDelegate.swift:997`, выбранной считает иконку с `name == currentIconName`, смену делает системным `application.setAlternateIconName(name)`. Показывает картинки через `UIImage(named: icon.imageName, in: getAppBundle())` (`ThemeSettingsAppIconItem.swift:384`). Значит **новый экран не нужен**, нужно добавить наши иконки в этот список.

Что делаем:

| Шаг | Что | Где |
|---|---|---|
| 1 | Нарисовать иконки (PNG без прозрачности): **белый знак на чёрном** (основная) и **чёрный знак на белом**, при желании ещё несколько цветных. Размеры как у существующих: `@2x`, `@3x`, iPad 76, 152, 167, значки уведомлений | `overlay/Telegram/Telegram-iOS/<Имя>.alticon/*.png` |
| 2 | Основная иконка приложения: заменить файлы `DefaultAppIcon.xcassets` и `AppIcons.xcassets/BlueIcon.appiconset` нашими (overlay умеет заменять файлы) | `Telegram/Telegram-iOS/` |
| 3 | Добавить имена папок в список `alternate_icon_folders` | `Telegram/BUILD:329`, хук в BUILD-файл |
| 4 | Описать иконки в `AlternateIcons.plist` и `AlternateIcons-iPad.plist` (`CFBundleIconFiles`, `UIPrerenderedIcon`). Свои записи кладём в свой plist и подключаем одной строкой `PlistBuddy merge` в `AddAlternateIcons.sh` | `Telegram/Telegram-iOS/AddAlternateIcons.sh` |
| 5 | Добавить `PresentationAppIcon(name:, imageName:)` для наших иконок в начало списка и объявить нашу основную иконку по умолчанию (`isDefault: true`), иначе при `is_appstore_build = false` ни одна иконка не будет помечена как текущая | `AppDelegate.swift:1000` (хук) |
| 6 | Подписи иконок: в `ThemeSettingsAppIconItem` названия берутся из `switch icon.name`, для неизвестных имён стоит «Icon». Хук подставляет наши названия («Чёрная», «Белая», …) | `ThemeSettingsAppIconItem.swift:384` |
| 7 | В нашем разделе «Mategram, Внешний вид» строка «Иконка приложения» с миниатюрой текущей иконки открывает тот же список | overlay |

Как проверим: после смены иконки iOS сам покажет системное окно «Вы изменили иконку». Это ограничение iOS, убрать его нельзя.

Риски: смена иконки через Sideloadly должна работать (иконки лежат в самом приложении), но я не проверял это на устройстве. Если переименование bundle id Sideloadly ломает альтернативные иконки, запасной путь: только основная иконка.

### 4.2. Логотип на кнопке отправки

Как это устроено (проверено): кнопка отправки в чате (`ChatTextInputActionButtonsNode`) в Telegram 13.2 может быть стеклянной (`usesSendButtonGlass`, когда не режим «пузырь»), её цвет задаёт свойство `customSendColor`, значок берёт из `PresentationResourcesChat.chatInputPanelSendIconImage`. В более старой ветке и в панели вложений круг с стрелкой рисуется в `chatInputPanelSendButtonImage` (круг цветом `actionControlFillColor`, стрелка цветом `actionControlForegroundColor`). Эти же картинки использует панель вложений (`AttachmentTextInputPanelNode.swift:1013,1945`) и лист «Отправить» (`ChatSendMessageActionUI/SendButton.swift:202`).

Что делаем:

| Шаг | Что | Где |
|---|---|---|
| 1 | Нарисовать наш знак в коде (Core Graphics): скруглённый треугольник с вогнутым основанием `M 0 -62 L 62 56 Q 0 22 -62 56 Z`, обводка 104 с круглым стыком, поворот 36 градусов, масштаб под размер кнопки. Без картинок, чёткий на любом экране | `overlay/Mategram/Brand/MategramLogoDrawing.swift` |
| 2 | `chatInputPanelSendButtonImage`: вернуть **белый круг и чёрный знак** независимо от темы, добавить тонкую обводку, чтобы белый круг был виден на светлой теме | хук в начале функции `PresentationResourcesChat.swift:365` |
| 3 | `chatInputPanelSendIconImage`: вернуть **чёрный знак** (без круга) для стеклянной кнопки | хук `PresentationResourcesChat.swift:383` |
| 4 | Стеклянная кнопка: выставить `customSendColor = .white`, тогда подложка окрасится в белый (строка `ChatTextInputActionButtonsNode.swift:559`) | хук рядом с созданием кнопки |
| 5 | Оставить штатными значки режимов «править» (галочка), «платное сообщение» (звезда), «запланировать» и «слот медленного режима»: заменяем только обычную отправку | условие в хуке |
| 6 | Кэш: картинка кэшируется под ключом темы (как у Telegram), не пересоздаётся на каждый кадр | `theme.image(key)` |

Состояние «кнопка выключена» остаётся штатным (альфа 0,4).

### 4.3. Секреты GitHub

`py -3 scripts/set_github_secrets.py --repo <владелец>/<репозиторий>` записывает `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в секреты репозитория через `gh secret set`. Значения скрипт берёт из переменных окружения или из локального файла `secrets.local.json`, который лежит в `.gitignore` и никогда не попадает в git. В самом скрипте и в репозитории ключей нет. Workflow читает те же имена секретов (как в вашем `mindgram.yml`).

## 11. Что я знаю точно, а что нет

- **Точно (проверено в коде):** логика функций Swiftgram и режима призрака Ghostgram (я читал реализацию), места вставки в Telegram 13.2 (найдены и применены скриптом), сборка с `app.mategram.ios` (профили созданы и читаются).
- **По символам и строкам (не по коду):** логика Nextgram: из IPA восстановлены имена классов, полей, тексты интерфейса и связи классов с экранами Telegram. Как именно устроена, например, маска кружка внутри, видно лишь частично. Для ядра Nextgram идёт декомпиляция в Ghidra (см. раздел 12).
- **Оговорка по тяжёлым функциям:** оценку сложности я делаю по объёму и зависимостям, а время зависит от тестов на устройстве.

## 12. Декомпиляция ядра Nextgram (Ghidra)

Ghidra декомпилировала 276 функций ядра Nextgram (`TelegramCoreFramework`: всё с `Nextgram` в имени и крупные функции модуля `NGSettings`). Что подтвердилось по настоящему коду, а не по именам:

| Функция | Что нашёл в коде | Что это значит для нас |
|---|---|---|
| Ускорение скачивания (`getNGDownloadPartSize`) | Читает настройку `downloadSpeedBoost`: значение «medium» даёт часть 0x80000 (512 КБ), для файлов не больше 0x100001 байт (около 1 МБ) оставляет размер по умолчанию, иначе размер части по умолчанию. Логика **идентична Swiftgram** | Берём логику Swiftgram как есть (#92) |
| Фильтр zalgo (`stripZalgo`) | Читает флаг `zalgoFilterEnabled`; если выключен, возвращает строку без изменений; если включён, проходит по юникод-скалярам строки и собирает новую строку без «ломаных» знаков | Фильтр по диапазонам комбинирующих знаков (#70) |
| Автопрокси (`NextgramAutoProxyManager`) | `start(ownerId, account, network)` подписывается на общие настройки прокси (`SharedDataKeys.proxySettings`). `refresh()` работает, только если включено и в списке **не меньше двух** прокси: тогда по каждому серверу параллельно запускается проверка с **таймаутом 5 секунд**, результаты собираются вместе и применяются | Реализуем так: две и больше прокси, опрос всех раз в N минут, переключение на самый быстрый доступный (#45) |
| Голосовой чейнджер (`NextgramVoiceEffectProcessor`) | Обрабатывает **чередующиеся** 16-битные (и вещественные) сэмплы блоками: каждый сэмпл переводит в число от -1 до 1 (деление на 32768), пропускает через эффект со своим состоянием на каждый канал, возвращает назад с ограничением по границам. Состояние (кольцевые буферы) выделяется по частоте дискретизации с минимумом 1024 сэмплов; каналов не меньше одного | Эффект во временной области на линиях задержки (сдвиг высоты и эхо), в реальном времени, без перекодирования (#76) |
| Экспорт и импорт настроек | `exportedSettingsData` и `importSettingsData`: обход всех ключей перечисления настроек и запись и чтение их значений как JSON (самые крупные функции модуля) | Один JSON со всеми ключами и версией (#88) |
| Live Activity (`NextgramLiveActivityStore`) | `recordNotification(title, message)` сохраняет заголовок, текст и время последнего уведомления; `snapshot()` собирает из них состояние для виджета (через общее хранилище) | Приложение пишет последние уведомления, виджет читает снимок (#89) |
| Маски в кружках | Слой маски (`NextgramRoundVideoMaskLayer`) и конфигурация кодируются и декодируются как JSON; активные слои выбираются отдельной функцией | Маска это упорядоченный список слоёв в JSON, как формат Ghostgram (#77) |

Не декомпилировано: интерфейсный фреймворк Nextgram (`TelegramUIFramework`, 106 МБ), в нём остаются экраны, стекло, NameDrop и камера. Для этого анализ займёт несколько часов и нужен отдельный запуск.
