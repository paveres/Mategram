# Mategram

Неофициальный клиент Telegram для iPhone на основе оригинального исходника Telegram-iOS. Сборка на GitHub Actions.

Главная идея: **наш код живёт отдельно от Telegram**, а в файлы Telegram вставляются только короткие строки-хуки. Когда у Telegram выходит новая версия, один скрипт переносит наши хуки на новый исходник.

## Структура

| Папка | Что внутри |
|---|---|
| `upstream/` | Чистый клон `TelegramMessenger/Telegram-iOS` (git, глубина 1). Руками не правим |
| `overlay/` | Наш код. Всё, что лежит в `overlay/`, копируется в корень `upstream/` как есть (например `overlay/Mategram/...` станет `upstream/Mategram/...`) |
| `hooks/` | Описания вставок в файлы Telegram, JSON. Папки с `_` в начале (`hooks/_examples`) по умолчанию пропускаются |
| `scripts/mategram.py` | Скрипт обновления и синхронизации (только стандартная библиотека Python 3) |
| `docs/` | Анализ исходника, карта точек подключения |
| `build-report/` | Отчёт последней синхронизации (создаётся скриптом) |
| `upstream.lock.json` | Какая версия Telegram сейчас взята |
| `.mategram/` | Служебные данные (снимки файлов старой версии для отчёта) |

## Как работает хук

Хук это запись в `hooks/*.json`: файл Telegram, **якорь** и что вставить.

```json
{
  "id": "ghost.read-receipt",
  "file": "submodules/TelegramCore/Sources/State/AccountViewTracker.swift",
  "action": "insert_before",
  "anchor": {
    "line": "строка, рядом с которой вставляем",
    "before": ["две-три строки выше"],
    "after": ["две-три строки ниже"]
  },
  "text": ["if !MategramGhost.allowsReadReceipt(peerId) { return }"],
  "required": true
}
```

Якорь ищется по тексту, а не по номеру строки, поэтому сдвиги кода не страшны. Вставленные строки помечаются `// MATE:<id>`, чтобы повторный запуск ничего не дублировал.

Как скрипт ищет место:
1. **Точно**: строка совпала, соседние строки совпали. Применяется.
2. **Приблизительно**: строку чуть изменили (например, добавили параметр). Если уверенность 0,93 и выше, применяется сам и попадает в отчёт. Если ниже, не применяется, а показывается в отчёте как «нужна проверка».
3. **Не найдено** или **несколько одинаковых мест**: не применяется, в отчёт попадает кусок изменений Telegram рядом с этим местом (разница между старым снимком файла и новым).
4. **Файл переехал**: ищет файлы с тем же именем и показывает их.

Если есть проблемы с обязательными хуками, скрипт завершается с кодом 1, и сборка на GitHub Actions останавливается раньше, чем дойдёт до компиляции.

## Команды

```
py -3 scripts/mategram.py status
py -3 scripts/mategram.py sync --dry-run
py -3 scripts/mategram.py sync
py -3 scripts/mategram.py fetch --latest
py -3 scripts/mategram.py fetch --tag release-13.3
py -3 scripts/mategram.py add --id ghost.x --file <путь> --line <N> --text "<код>"
py -3 scripts/mategram.py reanchor
py -3 scripts/mategram.py codesigning
py -3 scripts/mategram.py config --api-id <id> --api-hash <hash>
py -3 scripts/mategram.py selftest
```

`codesigning` переиздаёт фейковые профили подписи под `app.mategram.ios` (по умолчанию `team_id` это строка-заглушка `MATEGRAM00`, настоящий не нужен), результат в `build/fake-codesigning`. `config` пишет конфигурацию для `Make.py` (`bundle_id`, `team_id`, ваши `api_id` и `api_hash`, без iCloud).

Планы и анализ: `docs/PLAN.md` (этапы и логика каждой функции), `docs/ANALYSIS.md` (карта мест вставки в Telegram), `docs/FEATURES.md` (список функций).

| Команда | Что делает |
|---|---|
| `status` | Версия Telegram, число хуков и файлов overlay |
| `sync` | Сбрасывает `upstream/` к чистому виду, копирует overlay, применяет хуки, пишет отчёт. `--dry-run` только проверяет якоря, ничего не меняет |
| `fetch` | Скачивает новую версию Telegram (`--latest` последний релиз, `--tag`, `--branch master`), сохраняет снимки файлов с хуками, переключает `upstream/` и сразу делает `sync` |
| `add` | Создаёт хук: берёт строку N файла и 3 соседние строки с каждой стороны как якорь |
| `reanchor` | Обновляет якоря после того, как вы проверили отчёт: записывает новые строки и соседей из текущей версии |
| `selftest` | Проверка самого скрипта на временном репозитории |

## Как обновляться на новую версию Telegram

1. `py -3 scripts/mategram.py fetch --latest`
2. Открыть `build-report/sync-report.md`.
3. Если всё чисто, можно собирать.
4. Если есть «Needs review», «Anchor not found», «Ambiguous»: в отчёте видно, что изменил Telegram рядом с нашим местом. Поправить якорь вручную в `hooks/*.json` или запустить `reanchor` для приблизительных совпадений, затем снова `sync`.
5. Только после чистого отчёта собирать.

## Правила

- Свой код пишем только в `overlay/`. В `upstream/` руками ничего не правим: любая правка пропадёт при следующем `sync`.
- В файлы Telegram вставляем минимум: вызов нашей функции в одну строку. Вся логика у нас.
- Названия файлов и папок на английском. В коде нет комментариев и docstring, объяснения в README.
